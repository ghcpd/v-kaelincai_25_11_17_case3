# City Public Art Live Interaction Panel - Baseline vs Improved\n\nThis workspace contains two projects: `Project_A_BaselineLivePanel` (baseline) and `Project_B_ImprovedLivePanel` (improved). Both are static HTML demos designed to evaluate UI/UX improvements and include automated Playwright tests.\n\n## Getting started\n- Ensure Node.js (>=14), npm, python3, and curl are available.\n- From the root of this workspace: `./run_all.sh` to run both project tests and generate a comparison report.\n\n## Project A - Baseline\n- Live at `/Project_A_BaselineLivePanel/index.html`\n- Start server: `cd Project_A_BaselineLivePanel && nohup python3 -m http.server 3000 > /tmp/html_server.log 2>&1 &`\n- Tests: `cd Project_A_BaselineLivePanel && npm install && node tests/test_runner.js`\n- `run_tests.sh` orchestrates everything and writes results to `results_pre.json` and `log_pre.txt`.\n\n## Project B - Improved\n- Live at `/Project_B_ImprovedLivePanel/index.html`\n- Includes Tailwind (CDN), accessible controls, tabs, optimistic UI, and network simulation.\n- Start server & run tests similar to Project A. `run_tests.sh` writes `results_post.json` and `log_post.txt`.\n\n## test_scenarios.json\n- Defines UI/UX scenarios used by both project tests. Each scenario contains initial mock state injected via `localStorage.mockState`, a series of steps, and expected DOM assertions.\n\n## Test runner & evaluation metrics\n- Playwright scripts in each project read `test_scenarios.json` and execute steps.\n- Results are aggregated to `results_*.json` and logs to `log_*.txt`.\n- `run_all.sh` runs both sets of tests and then `compare_results.js` produces `compare_report.md`.\n\n## Detection logic\n- Projects are static HTML by default. If you prefer to use Next.js/React, create Next project and place page entrypoint at `/root/webapp/app/page.tsx`. This workspace uses static HTML for reproducibility.\n\n## Limitations and notes\n- Tests validate DOM and interaction behavior rather than pixel-perfect visual diffs.\n- Accessibility checks are basic (focus, ARIA attributes); use `axe-core` programmatically for stronger coverage.\n- Network behavior is simulated via a `network-toggle` button in the improved UI and via `appState` mocking.\n
