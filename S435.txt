Description
This experiment evaluates AI models’ ability to refactor and improve the UI/UX of a real-world web interface: the “Live Interaction Panel” of a city public art installation experience app.
The app runs as a web front-end served from /root/webapp and is used by visitors near city public digital art installations (dynamic lights, interactive screens, environmental sensors). Users open the app near a site to see nearby installations and interact in real time (vote on light themes, send live messages, reserve interaction slots, etc.).
The current Live Interaction Panel has these problems:
• All content (status, countdowns, interactions, forms) is crammed into a single scrollable page with no clear information hierarchy.
• Real-time status (crowdedness, health, queue length) visually blends with user action controls (buttons, forms), confusing users.
• Weak-network performance is poor: frequent live refreshes cause layout jank, delayed button responses, and lost feedback on actions.
• New users do not understand the typical flow (“select program → choose interaction → send”), leading to failed or invalid submissions.
• Accessibility is poor: low color contrast, small touch targets, dense animations, and no support for screen readers and keyboard navigation.
The improved version (Project B) must implement a redesigned, modern Live Interaction Panel UI with:
• Clear separation of status display vs user actions (e.g., top status area, bottom action area).
• Information architecture improvements (tabs or segmented controls for Program Interaction / Live Wall / Reservation Queue).
• Weak-network-friendly interaction patterns (manual refresh, optimistic UI for submissions, visible loading and retry states).
• Accessible, responsive layout using modern UI patterns and Tailwind CSS (or similarly expressive utility styling).
• Visual hierarchy, animations, and feedback that align with a high-quality UI/UX improvement.
Key evaluation criteria include:
• Correctness of the web app behavior (no broken interactions, stable layout).
• UI/UX quality: visual hierarchy, responsiveness, accessibility, and interaction feedback.
• Handling edge cases: weak networks, empty state, error state, over-crowded installations, non-interactive/maintenance states.
• Automated test cases for basic UI behavior and core flows.
• Reproducible environment and one-command test execution.
• Quantitative evaluation: task success/failure per test case, coverage of edge states, layout/interaction regressions.
